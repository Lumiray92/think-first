# ThinkFirst · 需求前分析

> 本文档包括 JTBD 分析、Pre-mortem 分析与 MVP 方案。

## 一、JTBD 分析

> 当 **做项目前，** 在 **刚有一个点子、准备动手之前** 时，
> 他们想要 **把模糊的想法变成一份清晰的需求分析文档**，
> 以便于 **不在错误的方向上浪费时间和精力或Token，做出真的有人用的东西，有市场潜力的东西**。
>
> 目前他们的方案是 **直接对 AI 说「我要做一个 XX的需求文档」或搜空模板根据以往自己的经验填写**，
> 但这个方案的问题是 **AI 会照做但可能跑偏，空模板不知道怎么填，没人告诉他们怎么做更科学「现在该关注什么、什么可以先不管」**。
### 1.1 用户画像（三维画像）

**用户名字**：小周

**一句话描述**：24 岁，第一次独立用 AI 做一个完整项目，不想再重蹈「做了三周发现方向错了」的覆辙。

| 维度 | 内容 |
|------|------|
| 表面属性 | 22-30 岁；学生 / 独立开发者 / 产品新人 / 非产品岗转做项目的人；每天能投入 2-4 小时做项目 |
| 行为习惯 | 会用 AI 编程工具；习惯直接对 AI 说「帮我做一个 XX的需求分析文档」；遇到问题先搜教程，不先想问题本身；项目启动时最兴奋，第 2 周开始迷茫 |
| 深层动机 | 害怕浪费时间（时间是最贵的成本）；想做出「真的有人用」的东西；想被同伴/老师/老板认为「靠谱、有方法」；不想再体验那种「做到一半发现全错了」的挫败感 |

**使用场景**：
- 场景 1：刚有一个项目点子，兴奋地打开 AI 工具，但不知道该先输入什么
- 场景 2：列了一堆功能，做着做着发现越做越乱，不知道哪些该砍
- 场景 3：项目卡住时，想回头检查「我一开始是不是就想错了」

### 1.2 任务分析

| 项目 | 内容 |
|------|------|
| **核心任务** | 在动手写代码之前，把一个模糊的点子，变成一份清晰、可执行、能直接交给 AI 或团队的需求分析文档 |
| **使用情境** | 项目启动阶段；用 AI 写第一行代码之前；比赛/作业/副业项目开始前 |
| **现有方案** | ① 直接对 AI 说「帮我做一个 XX的需求分析文档」；② 网上搜「需求分析模板」；③ 凭感觉列功能清单；④ 问朋友/同事「你觉得这个想法怎么样」 |
| **方案痛点** | ① AI 产出的东西和想象的不一样，来回改；② 模板是空的，不知道怎么填、填到什么程度算对；③ 功能越列越多，最后不知道从哪开始；④ 朋友只会说「挺好的」，得不到真实反馈；⑤ **最关键：不知道「现在这个阶段该纠结什么、不该纠结什么」，导致在错误的地方过度投入** |

### 1.3 三层次需求

| 层次 | 需求 |
|------|------|
| **功能需求** | 按阶段引导，明确每一步该产出什么、该关注什么重点；提供可填写的模板；最终产出一份结构化文档 |
| **情感需求** | 不焦虑、不盲目；有掌控感，知道「我现在在正确的路上」；不再有「做到一半发现全错了」的恐惧 |
| **社会需求** | 拿出一份看起来专业的需求分析文档，在同伴/老师/老板面前显得「有方法、靠谱」；不再被说「你就是拍脑袋做的」 |


### 1.5 三层任务对照

| 层次 | 任务 |
|------|------|
| 功能任务 | 产出一份需求分析文档 |
| 情感任务 | 减少焦虑，获得「我在正确路上」的确定感 |
| 社会任务 | 在他人面前显得有方法、靠谱 |

**关键提醒**：你的平台如果只满足功能任务（给模板、给流程），会沦为「另一个模板网站」。真正让用户留下来的是**情感任务**——那种「终于有人告诉我现在该干嘛、不用瞎纠结了」的确定感。这恰恰是你预设里「什么时间关注什么重点」真正值钱的地方。

## 二、Pre-mortem 分析

### 2.1 失败场景设定

> 现在是 **3 个月后**，这个需求分析产出平台已经彻底失败了。
>
> 具体表现是：
> - 注册用户不到 50 人，周活跃不到 5 人
> - 用户填完第一页就再也不回来了
> - 我自己也说不清它和「网上的需求分析模板合集」有什么区别
> - 项目已经 1 个月没更新了

### 2.2 失败原因列举

1. **用户根本不想「想清楚」** —— 他们只想快点做出东西，填模板感觉是在拖慢进度
2. **平台变成了「填空练习」** —— 用户机械填完模板，但并没有真正想清楚问题
3. **预设的痛点不成立** —— 「告诉用户关注什么」不是真需求，用户想要的是「直接给我答案」
4. **没有明确的价值锚点** —— 用户用完不知道得到了什么，说不清「这个平台帮我干嘛了」
5. **不引入 Agent 导致体验太静态** —— 就是个带引导的问卷，和看一篇博客没区别
6. **功能堆砌** —— 想把七个思维模型全塞进去，结果每个都做得浅
7. **没有验证就开做** —— 没找过真实用户，全凭自己想象
8. **文档产出物没人用** —— 生成的文档用户不会再看第二遍，也不会给 AI 或团队用
9. **阶段划分太细或太粗** —— 太细像流水线，太粗等于没引导
10. **和 AI 工具的关系没想清楚** —— 用户为什么不直接把你的引导词丢给 AI，而要来你的平台？

### 2.3 分类与评估

| 失败原因 | 类型 | 可能性 | 严重性 | 优先级 |
|---------|------|-------|-------|-------|
| 1. 用户不想「想清楚」 | 场景 | 高 | 高 | ⚠️ 必须解决 |
| 2. 平台变填空练习 | 需求 | 高 | 高 | ⚠️ 必须解决 |
| 3. 预设痛点不成立 | 需求 | 中 | 高 | ⚠️ 必须解决 |
| 4. 价值锚点不清 | 需求 | 高 | 高 | ⚠️ 必须解决 |
| 5. 体验太静态 | 技术 | 中 | 中 | ⚡ 建议解决 |
| 6. 功能堆砌 | 需求 | 高 | 中 | ⚡ 建议解决 |
| 7. 没验证就开做 | 习惯 | 中 | 高 | ⚡ 建议解决 |
| 8. 产出物没人用 | 场景 | 中 | 高 | ⚡ 建议解决 |
| 9. 阶段划分失衡 | 场景 | 中 | 中 | ✓ 考虑解决 |
| 10. 与 AI 关系不清 | 技术 | 中 | 中 | ✓ 考虑解决 |

### 2.4 预防措施

| 优先级 | 失败原因 | 具体预防措施 | 执行时间 |
|-------|---------|-------------|---------|
| ⚠️ | 用户不想「想清楚」 | 把「想清楚」包装成「省时间」：不是让你慢下来，是让你别白干。用「你花 10 分钟填这个，能省 3 天返工」的话术。首屏不放流程，放「一个失败案例」 | 设计前 |
| ⚠️ | 平台变填空练习 | 每个模板字段后加「为什么问这个」+「填错的典型样子」+「一个真实例子」。让用户理解，而不只是填写 | 开发中 |
| ⚠️ | 预设痛点不成立 | **先做 5 个用户访谈**，问「你上次项目做到一半发现方向错了是什么时候？当时要是有什么能帮你？」不要问「你想要一个引导平台吗」 | 立刻 |
| ⚠️ | 价值锚点不清 | 明确一句话：「10 分钟，把你的点子变成能直接交给 AI 的需求文档」。所有页面围绕这句话 | 设计前 |
| ⚡ | 体验太静态 | 第一版允许用户**边填边看到文档实时生成**，至少让产出物有「完成感」 | 开发中 |
| ⚡ | 功能堆砌 | 第一版**只做 JTBD + Pre-mortem 两个模型**。灵魂三问作为最后的自检卡片。其他五个模型进「不做清单」 | 立刻 |
| ⚡ | 没验证就开做 | 用「一个静态网页 + 手动引导」做 MVP，找 5 个人跑一遍，看他们卡在哪 | 第 1 周 |
| ⚡ | 产出物没人用 | 产出物必须能**一键复制成给 AI 的 prompt**，或导出成 markdown。让它有「去处」 | 开发中 |

### 2.5 不做清单（V1 版本）

| 不做的东西 | 理由 | 何时重新考虑 |
|-----------|------|-------------|
| 引入 Agent / 对话式引导 | 你已明确本阶段不做，且会大幅增加复杂度 | 静态流程验证成功后 |
| 七个思维模型全上 | 会稀释每个模型的深度，变成走马观花 | JTBD + Pre-mortem 验证成功 |
| 用户账号体系 | 第一版验证核心价值不需要登录 | 有留存数据后 |
| 多人协作 / 团队空间 | 偏离「个人想清楚」的核心场景 | 有明确团队需求时 |
| 精美的 UI 设计 | 第一版验证的是「流程是否有用」，不是「好不好看」 | 核心流程跑通后 |
| 自动生成完整需求文档 | 先验证「引导过程」有价值，再自动化 | 用户愿意手动填完之后 |

### 2.6 早期预警信号

1. **用户填到第 2 页就跳出** —— 说明流程太长或价值感建立太慢
2. **用户填完但产出物从不导出/复制** —— 说明产出物没价值，或没找到「去处」
3. **用户说「这不就是模板吗」** —— 说明引导没有产生「想清楚」的体验，只是填空
4. **访谈时用户说「挺好的」但不用** —— 典型「妈妈测试」失败，说明没戳到真痛点
5. **你自己说不清「用户用完得到了什么」** —— 价值锚点没立住，最危险的信号

### 2.7 最需要警惕的风险

**可能性高 + 严重性高**：**预设痛点不成立 + 价值锚点不清**。

这两个是连在一起的：如果没有先验证「用户真的想要被引导想清楚」，也没有一句话说清「用完得到什么」，那做出来的东西很可能就是一个「精致的模板合集」，用户看一眼就走了。

**对应的具体行动**：
1. **本周内**找 5 个目标用户做访谈，只问过去的行为，不问对想法的评价
2. **写下一句话价值锚点**，贴在所有设计稿最上面
3. **用静态网页 + 手动引导做 MVP**，第 1 周内跑通 5 个人

## 三、Mvp方案
### 3.1 核心假设

```markdown
我假设：
做项目需求分析的人 存在 「不想白干、怕方向从一开始就错」的问题，
他们愿意使用 一个分阶段引导 + 实时生成文档的网页 来 把模糊点子变成可交给 AI 或后端开发团队的需求分析文档，
因为它比 直接对 AI 说「帮我做一个 XX项目的需求文档」或搜空模板自己填 更快、更清晰、产出物真的能用。
```

### 3.2 验证标准

```markdown
如果：
- 10 个目标用户
- 在 2 周内
- 完整走完引导流程，并把产出的文档复制/导出，且其中 5 人表示「会拿这份文档去用 AI 或给同伴看」

则说明假设成立，值得继续投入。
```

**辅助观察指标**（不追求，只看）：
- 从进入到导出文档的平均耗时 < 15 分钟
- 中途退出率 < 40%

- 第 8 项（多模板）看似是核心，但第一版**只用「需求分析」一个场景**就能验证假设——多模板是扩张，不是验证。

### 3.4 P0 功能集（3 个）

#### P0-1：分阶段引导填写

- **为什么不砍**：这是「被引导想清楚」这个核心体验的载体，没有它平台就只是空模板
- **验证价值**：用户是否愿意跟着阶段走、是否真的产出了内容
- **做到什么程度**：JTBD 与 Pre-mortem 两个阶段，字段顺序固定，每步只问 2-3 个问题，**不追求一次问完所有字段**

#### P0-2：每字段引导层（为什么 + 错例 + 正例）

- **为什么不砍**：这是对抗「平台变填空练习」这个致命风险**唯一的防线**
- **验证价值**：用户是否因为看了引导而填得更具体、更少跳过
- **做到什么程度**：每个字段配一句「为什么问这个」、一个「填错的典型样子」、一个真实例子。**只做文字，不做动画**

#### P0-3：实时文档预览 + 导出 / 一键复制为 AI Prompt

- **为什么不砍**：产出物必须有「去处」，否则用户填完就走了
- **验证价值**：用户是否真的复制/导出，以及是否拿去用了
- **做到什么程度**：右侧实时渲染 markdown 预览；底部两个按钮：「复制为 AI Prompt」和「导出 Markdown」。**不做 PDF、不做精美排版**

**P0 检查**：
- ✅ 不超过 3 个
- ✅ 每个都是「没有它就无法验证核心假设」
- ✅ 核心功能要做到位——引导要真的帮人想清楚，导出要真的能用

### 3.5 不做清单（V1 版本）

#### 不做的功能

| 功能 | 不做的理由 | 何时重新考虑 |
|-----|----------|-------------|
| Agent 对话式引导 | 本阶段明确不做；会大幅增加复杂度，且会掩盖「静态流程是否有用」这个核心问题 | 静态流程验证成功后 |
| 用户账号体系 | 验证核心价值不需要登录，加登录会劝退第一批试用者 | 有留存数据、需要保存历史时 |
| 七大思维模型全覆盖 | 会稀释每个模型的深度，变成走马观花 | JTBD + Pre-mortem 验证成功 |
| 团队协作 / 评论批注 | 偏离「个人想清楚」的核心场景 | 出现明确的团队使用需求时 |
| PDF 导出 / 精美排版 | 第一版验证的是「内容是否有用」，不是「好不好看」 | 有用户明确要求打印/提交时 |
| 多模板选择（数据分析/自动化） | 一个场景足以验证假设，多场景是扩张 | 需求分析场景跑通后 |
| 社区分享 / 公开模板 | 没有足够内容前，社区是空的 | 有 100+ 用户产出物后 |
| 成就 | 与「想清楚」的核心价值无关 | 留存率成为主要问题时 |
| 历史项目列表 | 第一版不需要「回访」，只需要「用一次」 | 有用户主动问「我上次填的呢」时 |
| 暗黑模式 / 多语言 | 纯美化/扩张功能 | 有明确反馈时 |
| 教学视频 / 动画教程 | 文字引导层如果没用，视频也救不了 | P0-2 验证失败时再考虑 |

#### 不考虑的用户群

| 用户群 | 不考虑的理由 |
|-------|-------------|
| 企业团队 / 公司采购 | 需求复杂（权限、合规、协作），与个人工具定位不符 |
| 成熟产品经理 | 已有方法论和工具，不需要引导 |
| 只想「快速要答案」的人 | 他们要的是 Agent 直接生成，不是被引导思考——这不是本平台的用户 |
| 纯技术专家 / 资深开发者 | 他们的问题不在「想清楚需求」，而在实现 |
| 需要中英双语 / 海外用户 | 第一版只服务中文用户 |

#### 不追求的指标

| 指标 | 不追求的理由 | 替代关注点 |
|-----|-------------|----------|
| 注册用户数 | MVP 阶段验证价值比拉新重要 | 完整走完流程的人数 |
| 日活跃 / 周活跃 | 工具是「用一次」而非「每天用」，DAU 会误导判断 | 单次使用完成率 |
| 用户留存率 | 第一版不追求回访，只追求「用一次就值」 | 产出物被复制/导出的比例 |
| 功能完成度 | 功能多少不是重点 | 核心假设是否被验证 |
| 模板数量 | 数量不等于价值 | 单个模板的引导质量 |
| 页面停留时长 | 停留久可能是卡住了，不一定是好事 | 从进入到导出的完成率 |
