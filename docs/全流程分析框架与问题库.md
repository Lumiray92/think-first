# ThinkFirst 全流程分析框架（精简版）

> 按「心法篇」七个思维模型的重点整理：**先想清楚，再动手**。
>
> 贯穿案例：小李的极简待办清单（TodoFlow）。每一阶段只保留最关键的问题、动作和过关标准。

---

## 一、先记住七句话

| 思维模型 | 一句话重点 |
|----------|------------|
| 问题发现 | 好问题不是想出来的，是观察出来的 |
| JTBD | 用户不是买产品，而是雇产品完成一项任务 |
| 逆向思维 | 先假设项目会失败，再倒推怎么避免 |
| 减法思维 | MVP 是用最小投入验证核心假设，不是功能最少 |
| 故事思维 | 用户不是数据，是故事的主角 |
| 灵魂三问 | 用户是谁、痛点在哪、为什么选你 |
| 场景应用 | 思维工具是操作系统，场景决定具体约束 |

三条总原则：

1. **先想清楚，再动手**——AI 是执行者，你是导演。
2. **用户要具体到一个人**——说不出名字和使用场景，就是还没想清楚。
3. **每个阶段都要有出口标准**——答不上来就停下来补，不要靠写代码逃避思考。

---

## 二、全流程总览

| 阶段 | 心法 | 核心问题 | 关键产出 | 过关标准 |
|------|------|----------|----------|----------|
| S0 问题发现 | 问题发现 | 什么问题值得解决？ | 问题清单 + 选定问题 | 评分 ≥15，无红线，一句话说清 |
| S1 任务定义 | JTBD | 用户要完成什么任务？ | 一句话任务陈述 | 谁、情境、任务、结果齐全 |
| S2 用户理解 | 故事思维 | 用户是谁，经历了什么？ | 四幕故事 + 画像 + 旅程 | 能指出旅程最低点 |
| S3 风险预判 | 逆向思维 | 什么会导致失败？ | 失败原因 + 预防 + 信号 | ≥10 条，Top3 有对策 |
| S4 范围收敛 | 减法思维 | 第一版只做什么？ | 核心假设 + P0 + 不做清单 | 假设可验证，P0 ≤5 |
| S5 灵魂三问 | 灵魂三问 | 我真的想清楚了吗？ | 红绿灯 + 电梯演讲 | 三绿；黄灯有补齐计划 |
| S6 场景适配 | 场景应用 | 这个场景有什么硬约束？ | 场景约束 + 验收标准 | 约束可测，已进入需求 |
| S7 写 Prompt | 综合 | 怎么让 AI 准确理解？ | 故事化 Prompt + 结构化需求 | 六块齐全，检查清单全过 |
| S8 验证复盘 | 综合 | 假设成立吗？下一步做什么？ | 数据 + 决策 + 更新文档 | 有数据、有决策、有学习点 |

**三种用法：**

- **60 秒版**：只答 S1 的 JTBD 一句话 + S5 的灵魂三问，判断要不要做。
- **30 分钟版**：S0 → S1 → S4 → S5 → S7，适合个人小工具和自动化脚本。
- **完整版**：S0 → S8，适合要给多人使用的产品。

**红绿灯规则：**

| 状态 | 含义 | 下一步 |
|------|------|--------|
| 🟢 | 能用一句话清晰回答 | 继续 |
| 🟡 | 有想法但说不清 | 补信息，或先做最小实验 |
| 🔴 | 完全答不上来 | 停下来，回到对应阶段 |

> 灵魂三问全绿才全速开发；有黄灯可以有条件开始；有红灯先停下来。

## 三、各阶段重点

### S0 问题发现

**核心：先观察，再选问题。**

五个问题来源：

1. 自己每天重复做的事；
2. 身边人反复抱怨的事；
3. 现有工具用得不爽的地方；
4. 工作流程里经常卡住的地方；
5. 每次都要重新找、重新问的信息。

**烦恼日记**：连续 7 天，每天记 1～3 条。写清时间、场景、当时情绪、临时解决办法。

**两个评分：**

- 粗略筛选：`频率（1～5）× 痛苦度（1～5）`。16～25 很值得解决，9～15 可以解决，1～8 可能不值得。
- 五维评估：重复性、规则性、可验证性、敏感性、容错性，各 1～5 分。20～25 很适合，15～19 适合，10～14 谨慎，10 以下不建议。

**红线**：涉及资金安全、隐私数据、法律法规、长期高维护、高并发的，先放弃或降级。

| 要回答的问题 | 待办清单范例 |
|--------------|--------------|
| 你观察到的具体麻烦是什么？多久发生一次？ | 我每天上班要花 10 分钟把微信、便签、邮件里的待办抄到纸上；一天至少 3 次，漏掉就会忘事。 |
| 烦恼日记里，哪条出现最多、情绪最强？ | 10/14 便签丢了重写；10/15 微信刷屏漏了领导安排；10/16 纸没带。频率 5，痛苦 4。 |
| 频率分 × 痛苦分是多少？ | 5 × 4 = 20，属于很值得解决。 |
| 五维评分是多少？ | 重复性 5、规则性 4、可验证性 4、敏感性 2、容错性 5，合计 20，适合做。 |
| 有没有红线？ | 不碰支付、不收集隐私、只存本地，没有红线。 |
| 用一句话说清问题 | 帮我用一句话快速记下待办，并在每天固定时间提醒，做到不丢、不漏。 |

**要做的动作：**

- 记满 7 天烦恼日记，别只凭印象；
- 给每条打频率和痛苦分，选出前 3；
- 做五维评分和红线筛查，只留 1 个问题；
- 写成一句用户能听懂的话。

**过关：** 评分 ≥15，无红线，一句话能说清“帮谁、在什么情况下、解决什么麻烦”。

### S1 任务定义（JTBD）

**核心：用户不是买产品，而是雇产品完成一项任务。**

一句话模板：

> 当 **[某类用户]** 在 **[某个情境]** 下，他们想要 **[完成某个任务]**，以便于 **[获得某种结果或感受]**。目前他们用 **[替代方案]**，但问题是 **[痛点]**。

三层任务：

- **功能任务**：要完成的具体动作；
- **情感任务**：想获得的感受；
- **社会任务**：想在别人眼里成为什么样的人。

| 要回答的问题 | 待办清单范例 |
|--------------|--------------|
| 谁，在什么情境下？ | 经常被临时任务打断的上班族，在早上刚到工位、事情最多的时候。 |
| 他想完成什么任务？ | 把脑子里和聊天里的待办，在 30 秒内收进一个地方。 |
| 为了什么结果或感受？ | 不再漏事，下班时心里是清的。 |
| 功能、情感、社会任务分别是什么？ | 功能：快速记录、按时提醒；情感：安心、不焦虑；社会：在同事眼里靠谱、不掉链子。 |
| 现在用什么替代？问题在哪？ | 便签、微信收藏、纸质清单；问题是分散、会丢、不会提醒。 |
| 这句话能推导出功能吗？ | 能：快速录入对应输入框和快捷键；不丢对应本地保存；提醒对应定时通知。 |

**过关：** 谁、情境、任务、结果四要素齐全；能推导出至少 3 个功能；用户听完能认出自己。若只能写出一串功能，说明任务还没定义清楚。

### S2 用户理解（故事思维）

**核心：用户不是数据，是故事的主角。**

**四幕故事：**

1. **开端**：用户在什么场景下遇到问题；
2. **冲突**：尝试解决时卡在哪里、情绪如何；
3. **解决**：你的产品如何介入；
4. **结局**：用户的生活发生了什么变化。

**三维画像：**

- 表面属性：年龄、职业、设备、使用环境；
- 行为习惯：什么时候用、怎么用、用什么替代；
- 深层动机：真正害怕什么、渴望什么。用连续 5 个“为什么”往下挖。

**简化旅程：** 发现 → 首次使用 → 核心流程 → 长期价值。给每段打情绪分，**情绪最低点就是最大的改进机会**。

| 要回答的问题 | 待办清单范例 |
|--------------|--------------|
| 主角是谁？给他名字和一句介绍 | 小李，28 岁，互联网公司运营，手机里装着 12 个 App，事情一多就靠脑子记。 |
| 四幕故事是什么？ | 开端：早会下来 5 件事；冲突：便签、微信、纸上都有，下午找不到；解决：一个入口 30 秒记完，晚上统一提醒；结局：一周没漏事，下班能安心关电脑。 |
| 表面属性、行为习惯、深层动机？ | 表面：28 岁、运营、安卓；行为：每天打开微信 50 次、习惯语音；深层：怕被说不靠谱，想要掌控感。 |
| 连续问 5 个为什么 | 为什么记待办？怕忘。为什么怕忘？漏了会被领导说。为什么在意？想被当成靠谱的人。 |
| 旅程四段和情绪最低点？ | 发现：同事推荐；首次：打开就能输入；核心：30 秒记完；长期：每天提醒。最低点在首次——如果要注册，他可能直接关掉。 |
| 最低点对应什么改进？ | 免注册、打开即用、默认焦点在输入框。 |

**过关：** 能说出一个具体的人；能指出旅程最低点；每个功能都能对应故事里的一个冲突。

### S3 风险预判（逆向思维 / Pre-mortem）

**核心：先假设项目已经失败，再倒推原因。**

做法：

1. 假设 3 个月后项目死了，写下 **至少 10 条**失败原因；
2. 覆盖需求、技术、场景、习惯四类；
3. 给每条打“可能性”和“严重度”，选出最致命的前 3 条；
4. 为前 3 条写预防措施：谁、什么时候、花多少成本；
5. 设定可观察的失败信号，出现就调整。

常见失败模式：需求不清、功能太多、技术选型错误、用户群体错误、场景假设错误、高估使用意愿、低估迁移成本、完美主义、三分钟热度、缺乏验证。

| 要回答的问题 | 待办清单范例 |
|--------------|--------------|
| 假设 3 个月后失败，写 10 条原因 | ① 功能太多做不完；② 录入太麻烦没人用；③ 提醒不准；④ 数据丢失；⑤ 手机端体验差；⑥ 用户已有微信收藏；⑦ 三分钟热度；⑧ 没有推广；⑨ 只有我一个人用；⑩ 做成了另一个 Notion。 |
| 哪三条最致命？可能性和严重度？ | 录入麻烦（高/高）、功能太多（高/中）、只有我一个人用（中/高）。 |
| 每条怎么预防？谁、何时、多少成本？ | 录入麻烦→首屏只留输入框，第一周找 3 个同事试用；功能太多→P0 只留 3 个，砍掉分类和统计。 |
| 什么信号说明正在失败？ | 连续 3 天没有新增记录；试用者第二次不再打开；记录后仍靠纸提醒。 |
| 出现信号怎么调整？ | 先访谈 3 个试用者；若是录入问题就改语音输入；若是需求问题就回 S0 重选。 |

**过关：** 至少 10 条原因；前 3 条有具体预防措施；有可观察的失败信号；没有不可控的致命风险。

### S4 范围收敛（减法思维 / MVP）

**核心：MVP 是用最小投入验证核心假设，不是功能最少。**

核心假设模板：

> 我假设 **[某类用户]** 存在 **[某个问题]**，他们愿意使用 **[我的方案]** 来完成 **[某个任务]**，因为它比现有方案 **[更快 / 更简单 / 更便宜 / 更有效]**。

验证标准必须写成：**多少用户、多长时间、出现什么行为**。例如“2 周内 10 个试用者中至少 6 人连续 7 天每天记录 1 条以上”。

**功能三问：**

1. 没有这个功能，产品还能用吗？
2. 这个功能能验证核心假设吗？
3. 用户第一次使用就需要它吗？

三问都过 → **P0**；只过 1～2 问 → **P1**；都不过 → **P2 或不做**。P0 控制在 3～5 个。

**不做清单：**

- 不做的功能；
- 不考虑的用户群；
- 不追求的指标。

**投入产出：** 一年省下的时间 > 开发成本 × 3，才值得做。

| 要回答的问题 | 待办清单范例 |
|--------------|--------------|
| 核心假设一句话 | 我假设经常漏事的上班族，愿意用打开即记的工具，因为它比便签更快、比微信更不容易丢。 |
| 怎么算验证成功？ | 2 周内 10 个试用者中至少 6 人连续 7 天每天记录 ≥1 条。 |
| 第一版只做哪 3～5 个功能？为什么？ | P0：快速输入、本地保存、每日提醒。没有它们产品不能用，且正好验证核心假设。 |
| 哪些功能这版不做？为什么？ | P1：分类、搜索；P2：统计、同步、多人协作。它们不影响验证，先不做。 |
| 不做功能、不做用户、不追指标 | 不做登录、支付、后台；不服务团队用户；不追日活，只看 7 日留存和记录次数。 |
| 投入产出划算吗？ | 开发约 10 小时；每天省 10 分钟，一年约 60 小时，大于 30 小时阈值。 |

**过关：** 假设可验证；P0 ≤5 且每个都通过三问；不做清单明确；投入产出通过。

### S5 灵魂三问

**核心：用户是谁、痛点在哪、为什么选你。**

**1. 用户是谁**

- 具体到一个人，能说出名字、职业、使用场景；
- 分清用户、付费者、受益者，可能不是同一个人；
- 用“微信测试”：这句话发给他，他会不会觉得在说自己？

**2. 痛点在哪**

- 表面痛点 vs 深层痛点；
- 真痛点三个特征：**有情绪、正在发生、愿意付出**；
- 强度 = 频率（1～5）× 严重度（1～5）。16～25 很值得解决，9～15 可以解决，1～8 可能不值得。

**3. 为什么选你**

先看现有替代方案，再看差异化来源：

- 更聚焦：只解决一个场景；
- 更简单：步骤更少、上手更快；
- 更便宜：成本更低；
- 新场景：别人没覆盖的地方。

差异化必须对应用户真正在意的东西，否则只是自嗨。

**30 秒电梯演讲模板：**

> 很多 **[用户]** 在 **[场景]** 下会遇到 **[痛点]**。我的 **[产品]** 可以 **[核心价值]**，比 **[替代方案]** 更 **[差异点]**。

| 要回答的问题 | 待办清单范例 |
|--------------|--------------|
| 用户是谁？说一个具体的人 | 小李，28 岁运营，每天被临时任务打断，靠脑子记事。 |
| 痛点是什么？表面和深层分别是什么？ | 表面是待办分散；深层是怕漏事被说不靠谱。 |
| 痛点强度是多少？ | 频率 5 × 严重度 4 = 20，很值得解决。 |
| 现在怎么解决？为什么不够好？ | 便签 + 微信收藏 + 纸；分散、会丢、不提醒。 |
| 为什么选你？差异化在哪？ | 更简单：打开就输入，30 秒记完；更聚焦：只做记录和提醒，不做项目管理。 |
| 30 秒电梯演讲 | 很多上班族的待办散在微信、便签和纸上，最后漏事。TodoFlow 打开就能记，30 秒收完，到点提醒。比便签快，比微信不容易丢。 |
| 红黄绿结论 | 用户 🟢、痛点 🟢、为什么选你 🟡——差异化还不够硬，先找 5 个用户验证“打开即记”是否真的更快。 |

**过关：** 三问全绿才全速开发；黄灯要有补齐计划；红灯停止。黄灯时的最小实验通常比继续写代码更有效。

### S6 场景适配

**核心：同一套思维，不同场景的约束不同。**

| 场景 | 重点 | 关键约束 |
|------|------|----------|
| 数据分析 | 先有业务问题，再找数据 | 受众是谁、支持什么决策、3～5 张图讲完、数据质量可信、每张图有结论 |
| 自动化脚本 | 频率 × 单次耗时 × 年限 | 先手动跑通，再自动化；不覆盖原始文件；出错必须提示；结果可抽查 |
| 个人工具 | 解决自己本周真实痛点 | 只做一个核心功能；打开到完成 ≤3 步；不过度设计；先自己用一周 |
| 家人工具 | 老人、小孩、非技术用户 | 字 ≥20px；按钮 ≥屏幕宽 40%；≤3 步；反馈清楚；容错高；不登录、无广告 |

**自动化值不值得做：** 频率、单次耗时、使用年限各打 1～5 分，总分 ≥12 值得做，9～11 可以考虑，≤8 不建议。

| 要回答的问题 | 待办清单范例 |
|--------------|--------------|
| 属于哪类场景？为什么？ | 个人工具，主要是我自己每天用。 |
| 这个场景的硬约束是什么？ | 打开到记完 ≤3 步；手机单手可用；离线可用；不登录。 |
| 按场景重点补哪几个问题？ | 个人工具只保留一个核心功能；不做分类和统计；先自己用一周。 |
| 验收标准是什么？ | 从点开到记完 ≤30 秒；连续 7 天使用；无数据丢失。 |

**过关：** 场景明确；至少 3 条硬约束写进需求；验收标准可测量。

### S7 写 Prompt 与开发前检查

**核心：AI 是执行者，你是导演。Prompt 的质量取决于前面想得有多清楚。**

**故事化 Prompt 四要素：**

1. **身份**：用户是谁；
2. **现状**：他现在怎么做事；
3. **痛点**：哪里卡住、情绪如何；
4. **期望**：他想达到什么结果。

**结构化需求六块：**

1. 背景：为什么做；
2. 核心问题：要解决什么；
3. 第一版只做：P0 清单；
4. 明确不做：不做清单；
5. 异常情况：出错、没数据、权限不足时怎么办；
6. 验收标准：怎么判断做对了。

**开发前 60 秒三问：** 用户是谁？痛点在哪？为什么选你？

**5 分钟检查：** 问题真不真、用户具体不具体、风险有没有对策、P0 是否 ≤3～5 个、灵魂三问是什么颜色。

| 要回答的问题 | 待办清单范例 |
|--------------|--------------|
| 60 秒三问能答吗？ | 用户：小李这样的上班族；痛点：待办分散会漏；为什么选我：打开即记、30 秒完成。 |
| 故事化 Prompt 四要素 | 身份：28 岁运营；现状：待办散在微信、便签、纸；痛点：漏事被批评；期望：一个入口 30 秒记完并提醒。 |
| 结构化需求六块 | 背景：待办分散；核心问题：会漏事；只做：输入、保存、提醒；不做：登录、分类、统计；异常：存储失败要提示；验收：30 秒记完、7 天不丢。 |
| 开发前检查清单全过吗？ | 问题真、用户具体、风险有对策、P0 只有 3 个、三问两绿一黄——先做 5 人试用再补差异化。 |

**过关：** 六块齐全；P0 明确；验收标准可测；红黄绿有结论。

---

### S8 验证与复盘

**核心：MVP 不是缩小版产品，而是一次实验。**

按 S4 的验证标准收数据，只记录与假设有关的行为，不被“大家都说好”这类反馈带偏。

三种结果：

- **假设成立**：保留 P0，再考虑加一个 P1；
- **部分成立**：只改一个变量，再做一轮；
- **不成立**：回到 S0 或 S1，不要硬救。

| 要回答的问题 | 待办清单范例 |
|--------------|--------------|
| 实际数据是什么？ | 2 周 10 人试用，6 人连续 7 天记录，日均 2.3 条。 |
| 假设成立吗？ | 核心假设成立：打开即记确实被使用；但提醒被忽略。 |
| 下一步做什么？ | 保留 P0，改提醒文案和时间；暂不加分类。 |
| 学到什么？文档怎么更新？ | 用户要的是“不漏”，不是“管理”；把这句话写回需求文档。 |

**过关：** 有数据、有明确决策、需求文档已更新。

## 四、一页速查：TodoFlow

| 项目 | 结论 |
|------|------|
| 问题 | 待办散在微信、便签、纸上，会丢、会漏 |
| 用户 | 小李，28 岁运营，每天被临时任务打断 |
| JTBD | 当上班族在早上事情最多时，想 30 秒收完待办，以便下班时心里是清的 |
| 替代方案 | 便签、微信收藏、纸质清单；分散、会丢、不提醒 |
| 痛点强度 | 频率 5 × 严重度 4 = 20，很值得解决 |
| 差异化 | 更简单（打开即记）、更聚焦（只做记录和提醒） |
| 核心假设 | 经常漏事的上班族愿意用打开即记的工具 |
| P0 | 快速输入、本地保存、每日提醒 |
| 不做 | 登录、支付、分类、统计、同步、多人协作 |
| 验证标准 | 2 周 10 人试用，≥6 人连续 7 天每天记录 ≥1 条 |
| 电梯演讲 | 待办散在微信、便签和纸上会漏事；TodoFlow 打开就能记，30 秒收完，到点提醒 |
| 红绿灯 | 用户 🟢、痛点 🟢、为什么选你 🟡（先做 5 人试用补差异化） |

## 五、常见误区

| 误区 | 表现 | 纠正 |
|------|------|------|
| 把功能当任务 | “我要做一个带 AI 的待办 App” | 先写 JTBD：用户在什么情境下要完成什么 |
| 用户写成“所有人” | “适合所有上班族和学生” | 具体到一个名字、一个场景 |
| 先做再说 | 有想法立刻让 AI 写代码 | 先过灵魂三问和 Pre-mortem |
| 把 MVP 等同于功能少 | 随便砍几个功能就上线 | MVP 是验证核心假设所需的最小投入 |
| 只写正常流程 | 没考虑没数据、出错、权限不足 | 需求里必须有异常处理 |
| 没有验收标准 | “做得好看一点” | 写成可测的数字和行为 |
| 一次改多个变量 | 数据不好就大改版 | 一次只改一个变量，再做一轮 |
| 文档写完就丢 | 开发和需求两张皮 | 每次验证后更新同一份文档 |
